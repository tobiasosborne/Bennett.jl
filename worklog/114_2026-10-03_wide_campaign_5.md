**Bennett-czox — SoftFloat trace picks different methods than native dispatch** (0ca7e61, review-2 S3).
`reversible_compile(f, Float64)` compiles `f(::SoftFloat...)`; SoftFloat is not a subtype of Float64,
AbstractFloat, Real or Number, so a method or `isa` test specific to those takes another branch on the
trace. Witness gave (2, 1, true) on the Tuple route, and the hole also existed in the Float64 overload
itself (it predates d3d7ba1) and one level down, in helper calls (`h(x)=g(x)` with `g(::Float64)` next
to a generic `g`). New `_softfloat_dispatch_divergence(f, N)` in `src/softfloat_dispatch.jl` walks the
unoptimised typed code under both signatures in parallel (one Method typed twice keeps its statement
list; dead statements are wrapped `Core.Const(stmt)::Union{}`). Three flags: a call site selecting
different methods with either one user code; a statement live natively but dead on the trace; a Bool
constant that differs (`x isa Float64`). It stops at Base/Core/Bennett methods and recurses into
same-method calls with different argument types (finds `map(g,(x,))`). Departure from strict
`which()` equality: a Base root (`-`, `+`, `abs`) always resolves differently under SoftFloat, so the
root uses the user-code rule too and still delegates. Float64 overload now throws ArgumentError naming
the bead; the Tuple overload sends a divergent `f` down the native-IR route (as before 19jw). Tests:
new `test/test_czox_softfloat_dispatch_divergence.jl` 66 pass (witness, AbstractFloat/Real, 2-arg
partial specialisation vs native compares, helper/isa/map, detector `nothing` on 17 generic functions,
bit-exact delegation incl. specials); 26-file run 170503 pass, 1 broken. Gate counts unchanged.
Left out: splatted calls, `ifelse(x isa Float64,...)`, `invoke`, type-unstable sites.

**Bennett-cohv — escaping loop-header pointer lost its provenance** (def89bc, review-2 S2). i5zn's
`_loop_hold!` held `vw[p]` of a load-tainted header pointer, but loads/stores through it read
`ptr_provenance[p]` (per origin: alloca, idx OPERAND, predicate WIRE); after the loop both came from
the last replay, so the exit block used the post-exit address: (20,true), correct 10, fold off and on.
Fix in `src/lowering/cfg.jl` only: a hold-set name with provenance goes through `_loop_hold_ptr!`
(per origin, idx wires and predicate wire each held as `active ? fresh : held`, no gate when the wire
is identical every visit; each replay must yield the same origins or an AssertionError names the
bead), then `_loop_publish_ptr!` sets `ptr_provenance[p]` to the held wires (`__cohv_idx_<p>_<k>`) and
deletes the stale `vw[p]`, so a non-provenance reader fails loud. It also fixes load-dependent
pointer-selects and GEP-of-GEP pointers that used to hit i5zn's "has no wires" AssertionError. Tests:
new `test/test_cohv_loop_held_ptr.jl` 281 pass (own array interpreter, all 256 inputs, fold off/on,
K=1:5; exit load and exit store for 6 pointer kinds); red = 55 fail + 16 error; 16-file run 4070,
7-file run 213844. No pinned baseline moved; witness K=2 fold=false 6575 -> 6575, fold=true
1119 -> 1079. Left out: pointer-typed loop-carried header phi, header allocas.

**Bennett-0gm7 — no-return proof looked at one next instruction** (13ddc8d, review-2 S7). 08xz's
`_is_noreturn_call` (`src/extract/instructions.jl`) accepted a runtime-throw call only when the NEXT
instruction was `unreachable`; with `llvm.assume`/dbg/lifetime between, the block still ended in
`unreachable` but hit the loud U15 error. Now it scans forward to the terminator and accepts only an
`unreachable` one, skipping direct calls to `_NORETURN_SCAN_SKIP_PREFIXES` (`llvm.dbg.`,
`llvm.lifetime.`, `llvm.assume`, `llvm.experimental.noalias.scope.decl`, `llvm.trap`) and further
`_RUNTIME_THROW_PREFIXES` calls; two throws in a row are accepted (if the first returned the second
runs, so the block still cannot reach live code) and the same rule drops the second. Anything else
(store, other/indirect call, non-call, `ret`/`br`) ends the scan as "may return". Deliberately not
skipped: `llvm.donothing`, `llvm.sideeffect`, `llvm.debugtrap`, `llvm.invariant.*`, `julia.*`.
vector_vm_walk.jl inherits the fix (comment-only change). Tests: new
`test/test_0gm7_noreturn_tail_scan.jl` 34 pass (witness, 10 accept fixtures over 256 inputs, 6 reject
fixtures, direct helper check; no Case-A vm fixture, the helper is checked directly); 25-file run
67524 pass, 1 broken. Gate counts unchanged. Bennett-awqx stays open (see Annotated).

**Bennett-rrop — composed GEP indices re-sign-extended** (f110cea, review-2 S1). Third consecutive
fix to GEP index composition (jkf0 -> gw0r -> rrop). gw0r composed at `W = max(index_bits(n)+1,
operand widths)` and sign-extended every operand to W, including an already composed index; a
composed value is only known mod its width (i4 6 scaled x2 = 12 reads as -4 when an i8 GEP widens it,
so 12-12 became -16, MUX zero-extended to 240, last slot read: 40 instead of 10; `verify_reversibility`
true). Invariant (proof comment at the site, `src/lowering/aggregate.jl`): an origin index is an exact
constant, a raw operand (signed value D), or a composed value of exactly W wires holding D mod 2^W with
W = idx_bits(n)+1 fixed per alloca and never widened; operands are sign-extended first, then scaled,
then summed mod 2^W. An in-range D < n <= 2^(W-1) reads as D under MUX zero-extension and the shadow
path's low-bit read; constant finals stay exact; the spare bit keeps out-of-range finals off valid
slots (usable by a later runtime bounds check, Bennett-usly). The persistent slab composes at the pmap
key width `_K_bits(impl)` (`resolve!` demands exactly that; 64 bits threw a width mismatch). Design
chosen by measuring gates emitted in `_compose_gep_index!`: gw0r fixtures 41765 -> 25432, jkf0
648 -> 392, dm9r 78 -> 46 (64-bit composition ~10x more); S1 witness 5596 -> 5524; no pinned baseline
moved. Tests: new `test/test_rrop_gep_chain_index_residue.jl` 344/344 (S1 witness, three-deep and
persistent-slab witnesses, 164 generated 2-3 deep chains over mixed element and index widths 2-64, all
256 inputs vs a byte-level model; old rule replicated by method override = 24 fail + 1 error); 17-file
run 4548, 28-file GEP/memory/sret run 4143. Left out: Bennett-dsd3 (narrowed, not closed).

**Bennett-koi8 — narrowing accepted comparisons optimised IR had folded** (c443621, review-2 S4).
UInt8 `(x>=248)&(x<=248)` becomes `icmp eq x,-8`, true at x=8 at W=4. The generated corpus (804
predicates, 8040 compiles) found 166 accepted-and-wrong cells on main in four families: eq/ne against a
high or negative constant; a signed ordering folded from an unsigned one (`x<0x80` -> `sgt x,-1`,
`(x<2)|(x>=0x80)` -> `slt x,2`); an add-then-ult range check; Int8 `x<0` -> `lshr x,7` (wrong at W=7).
New rule (`src/narrow.jl`, one line in `src/extract/callees.jl`): at W<S eq/ne accept only
0..2^(W-1)-1 (only there do sext(p)==c and zext(p)==c both reduce to p==c; a hand-written `x==5` at
W=3 is now a refusal). `_narrow_ir(...; optimized=true)` (`reversible_compile` passes `optimize`):
for optimised IR at W<S every signed ordering is refused, both compare operands must be "faithful"
(v_S = e(v_W) under sext and zext: arguments, and/or/xor of them, `and` with a constant in
smin..smax(W), or/xor with 0..smax(W), select/phi; refuses the `ult (add x,-9),4` fold), and
`lshr/ashr x, S-1` is refused. Corpus, same seed: 4108 accepted / 3932 refused / 166 wrong ->
3471 / 4569 / 0; 471 of the lost acceptances were correct programs. User-visible cost: every Int8
ordering at W<8 with optimize=true is refused, the error says to use optimize=false. Tests: new
`test/test_koi8_narrow_folded_cmp.jl` (witness, named folds, 444 predicates x 5 widths x 2 modes:
1941 accepted, 2499 refused, 0 wrong; 26 pass, 1 broken); the two 6p8j `@test_broken` shapes are now
passing refusal tests; test_narrow (x==5 moved to W=4), test_mrhg, test_g7d6 updated; 4-file run
