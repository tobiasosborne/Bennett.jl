### What landed — Bennett.jl (all gated on `ptr_cells=true`)

- **D5a — call emission on `_lookup_callee` MISS** (`instructions.jl`, the U15
  arm). A `.ll` call whose callee is not a registered Julia `Function` but IS
  an `LLVM.Function` (the LAST call operand) lowers to a `Symbol`-callee
  `IRCall`. `LLVM.isdeclaration` is NOT consulted to branch the shape — both
  libc (`malloc`/`free`) and in-module (`ht_hash`/`ht_new`) emit the same
  `Symbol`-callee `IRCall`; BVM disambiguates by name (`_HEAP_DISPATCH` vs
  guard-5). ptr args/returns are 64-bit cells; NOTHING is skipped (unlike the
  Julia swiftcc pgcstack-skip loop — the C closed world has no synthetic frame
  arg).
- **D5b — void shapes** (the chunk's real design knot). Two sub-problems, both
  "no value to carry":
  - **void RETURN** (`ret void` in `ht_free`/`ht_put`/`ht_third_pass`/`ht_grow`):
    a NEW `IRRet()` **void form** — `op::Union{IROperand,Nothing}` widened, the
    zero-arg constructor sets `op === nothing` + `width == 0`. The
    value-bearing `IRRet(op::IROperand, w)` is BYTE-IDENTICAL and STILL asserts
    `width >= 1` — so `test_k7al`'s `@test_throws "width=0" IRRet(a, 0)` is
    intact (the void form is a SEPARATE constructor, not a relaxation). The
    function-level `ret_width = 0` / `ret_elem_widths = Int[]` derivation
    (`module_walk.jl`) is the matching half.
  - **void CALL** (`call void @free`/`@ht_put`): `IRCall.dest::Symbol` is
    MANDATORY + `ret_width >= 1`, so a void call carries the auto-named
    never-read `dest` (the naming pass ALREADY assigns one — `module_walk.jl`
    ~207) + a `ret_width = 64` SENTINEL. The dest/width are NEVER read: BVM
    routes a void callee to `IntrinsicFree` (no dest) or guard-5 with empty
    `fe.returns` ⇒ EMPTY targets. 64 (not 0) keeps a uniform
    `ret_width == cell-width` IR invariant for every C call.
- **D5c — `alloca ptr` → `IRAlloca(dest, 64, 1)`** (`instructions.jl` alloca
  arm). The C `%t.addr = alloca ptr; store ptr %t, ptr %t.addr` idiom — one
  64-bit cell. Without it the matching `store ptr` (D3) would target a dest
  with no prior `IRAlloca` (the haiy chunk-C assumption). `alloca ptr, i32 N`
  carries the count through the same `n_elems_op` logic as the integer arm.
- **D6 — `extract_parsed_ir_set_from_ll(path; ptr_cells) ->
  Vector{Pair{Symbol,ParsedIR}}`** (`entry.jl` + `_module_to_parsed_ir_set` in
  `module_walk.jl`). Walks EVERY defined function through the SAME single-fn
  core walker; `declare`d libc (empty blocks) skipped; fails loud on zero
  defines. Exported.

### What landed — BVM (the two preconditions + the void-form consumption)

- **`_callee_sym` helper** (`ingest_body.jl`): `nameof` for a `Function`,
  identity for a `Symbol`. Replaced all 11 textual `nameof(inst.callee)` sites
  (8 dispatch decision points). NOT type-piracy on `Base.nameof` (Rule 14) — a
  local helper for exactly the two `IRCall.callee` shapes. This is the
  chunk-A/B precondition: `nameof(::Symbol)` does not exist, so a Symbol-callee
  IRCall MethodError'd before reaching any guard.
- **IRRet void-form consumption** (`ingest.jl:593`): `term.op === nothing` ⇒
  `EndInstruction(routine, Symbol[])` (empty returns), placed BEFORE the
  value-bearing arm so `_lower_operand(nothing)` is never hit. The matching
  `_declared_returns` already returned `Symbol[]` for a missing/void IRRet.
