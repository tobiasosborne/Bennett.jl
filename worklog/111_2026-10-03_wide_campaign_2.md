**Bennett-o9sv — closure captures silently became circuit inputs** (db772ca). Julia passes a
capturing closure's own object as a hidden leading `#self#` parameter, which the walker treated as
an `8*sizeof`-bit input: `x -> x - k` compiled to widths [8, 8] and `simulate(c, Int8, (10, 7))`
gave -3 where f(10) = 3. Decision, in `src/Bennett.jl` (Tuple overload): a closure type (a
`Function` subtype whose name starts with `#`, `sizeof > 0`) is BOUND when its type is isbits and
holds no Ptr (`_closure_capture_bytes` builds the bytes leaf by leaf via `fieldoffset`, padding
zeroed; `_bind_closure_capture` wraps NOT gates before and after the circuit and moves the self wires
into the ancillae, exact because inputs are preserved). Every other capture (Ref, Vector,
Core.Box, non-isbits) is REJECTED with an ArgumentError naming the fields and Bennett-o9sv, checked
before both tabulate exits so a Ref is never frozen into a QROM table; any capture is also rejected
under `bit_width>0` and `target=:reversible_vm`. Binding happens AFTER the compile cache so
same-type closures with different captures never share a circuit; consequence: repeat compiles of
a capturing closure are no longer `===` (still `===` for everything else). New
`test/test_o9sv_closure_captures.jl` 83 pass; 15 targeted files 7399/7399. Gate counts unchanged
(no lowering touched). Left out: callable-struct fields and `Base.Fix1/Fix2` (functors, names do
not start with `#`) still become circuit inputs, pinned by test_4ddk; the Float64 overload's
wrapper closure captures the user's `f`, so a capturing `f` binds through the same path (untested).
