## Session log — 2026-10-03 — batch 5 landed: Bennett-o9sv (db772ca), Bennett-p9a0 (5608d9f), Bennett-ytpe (fc6dfdc), Bennett-ovzp (af9f308)

**Bennett-o9sv — closure captures silently became circuit inputs** (db772ca). Julia passes a
capturing closure's own object as a hidden leading `#self#` parameter, which the walker treated as
an `8*sizeof`-bit input: `x -> x - k` compiled to widths [8, 8] and `simulate(c, Int8, (10, 7))`
gave -3 where f(10) = 3. Decision, in `src/Bennett.jl` (Tuple overload): a closure type (a
`Function` subtype whose name starts with `#`, `sizeof > 0`) is BOUND when its type is isbits and
holds no Ptr (`_closure_capture_bytes` builds the bytes leaf by leaf via `fieldoffset`, padding
zeroed; `_bind_closure_capture` wraps NOT gates before and after the circuit and moves the self wires
into the ancillae, exact because inputs are preserved). Every other capture (Ref, Vector,
Core.Box, non-isbits) is REJECTED with an ArgumentError naming the fields and Bennett-o9sv, checked
before both tabulate exits so a Ref is never frozen into a QROM table; any capture is also rejected
under `bit_width>0` and `target=:reversible_vm`. Binding happens AFTER the compile cache so
same-type closures with different captures never share a circuit; consequence: repeat compiles of
a capturing closure are no longer `===` (still `===` for everything else). New
`test/test_o9sv_closure_captures.jl` 83 pass; 15 targeted files 7399/7399. Gate counts unchanged
(no lowering touched). Left out: callable-struct fields and `Base.Fix1/Fix2` (functors, names do
not start with `#`) still become circuit inputs, pinned by test_4ddk; the Float64 overload's
wrapper closure captures the user's `f`, so a capturing `f` binds through the same path (untested).

**Bennett-p9a0 — callee registry keyed by bare function name** (5608d9f). `_known_callees` is keyed
by `string(nameof(f))` and the LLVM symbol `j_<name>_<NNN>` carries no module, so with only
`B.same` registered a call to the unregistered `A.same` inlined `B.same`'s body (256/256 Int8
wrong, `verify_reversibility` true); `register_callee!` also overwrote same-named entries
silently. Fix: `src/extract/callees.jl` adds a ScopedValue `_CALLEE_ROOT` (`_CalleeRoot(sig, direct,
closure)`); on a demangled hit `_check_callee_identity` reads the root's typed `:invoke` edges
(falls back to the transitive closure), requires exactly one function of that name and that it
is the registered one, else errors naming Bennett-p9a0. `register_callee!` now throws when a
DIFFERENT function holds the bare name (same function: no-op). `entry.jl` wraps the walk in
`_with_callee_root(sig)`; `callgraph.jl` gains a by-signature `_transitive_callee_specTypes`. New
`test/test_p9a0_callee_module_identity.jl` 20/20 (red on main); related files green (4857 + 8227
pass among them). Gate counts unchanged. Stated limit: `.ll`/`.bc`/IR-string inputs have no Julia
root, so they still match by name only (an unregistered namesake there is undetectable).

**Bennett-ytpe — `llvm.fshl/fshr` returned a|b at shift 0** (fc6dfdc). `_handle_intrinsic`
(`src/extract/instructions.jl`) emitted `(a << s) | (b >> (W - s))` as written; at s = 0 mod W the
second shift is by W, which the barrel shifter masks to 0, giving `a | b` instead of `a` (fshl)
or `b` (fshr); constant amounts were never reduced mod W (>= W or negative hit the zmw3
out-of-range error or a wrong value). Review witness: 0x36 for 0x12. Fix: one branch for both
intrinsics. Constant amount: unsigned W-bit value mod W; k == 0 emits `dest = keep + 0`, else the
same shl/lshr/or as before (constant-rotate counts in SHA-256 and Feistel unchanged). Runtime
amount: `k = s & (W-1)`, `wk = W - k`, both shifts, `or`, `icmp eq k 0`, `select`. Runtime amount at
a non-power-of-two width is rejected with `_ir_error` naming Bennett-ytpe. New
`test/test_ytpe_funnel_shift.jl` 200/200 (i8 exhaustive in s, a and 8 values of b; constants;
i16/i64; i7; Julia `bitrotate` over all 256x256 inputs); 9 targeted files 4651/4651. No pinned
baseline moved, but a runtime-amount rotate is dearer: `bitrotate(x::UInt8, k::Int8)` = 676 gates
/ 136 Toffoli (the added and/sub/icmp/select).

**Bennett-ovzp — MUX-EXCH store of a negative constant threw InexactError** (af9f308).
`_operand_to_u64!` (`src/lowering/memory.jl`) built the 64-wire operands for the
`soft_mux_store/load_NxW` callees with the value-checked `UInt64(op.value)`, so `store i8 -1` through
a runtime-indexed pointer threw, for every registered MUX shape at i8/i16/i32. It was the only
checked conversion of that kind in src/; shadow, shadow-checkpoint and persistent arms go through
`resolve!`/`lower_call!`, were already correct, and are now pinned. Fix: `_operand_to_u64!(ctx, op,
width)` materialises `_const_value_mod(op, width)` (store value passes W; the idx operand passes 64,
always SSA there) plus a width range check. New `test/test_ovzp_negative_const_store.jl` 234 pass
(hand-built IR, all slots vs oracle `(f && i==j) ? C : v`, all 11 `_MUX_SHAPES_NW` shapes,
shadow W=8..64, shadow-checkpoint (9,8)/(5,16)/(3,32)/(2,64), persistent linear_scan i8); 10 related
files 12398 pass. Gate counts unchanged (only formerly-crashing constant stores change).
