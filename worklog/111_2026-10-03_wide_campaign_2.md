**Bennett-jkf0 — GEP-on-GEP lost pointer provenance** (bcded8f). When a GEP's base was itself a GEP
result its provenance (alloca, index) was dropped or reset: `lower_ptr_offset!` skipped every origin
with a runtime index, and `lower_var_gep!` overwrote the base index instead of adding to it, so
`q = &a[x&3] + 0` loaded through the legacy pre-store copy (0 instead of 42 on 256/256, with
`verify_reversibility` true). The persistent paths had the same bug (`p1 + 0` read slot 0). Fix, all in
`src/lowering/aggregate.jl`: `_compose_gep_index!` returns `base_idx + delta` (const/zero fold with no
gates, a runtime sum is a ripple add under `__jkf0_idx_<dest>_<k>`), used by all four GEP producers;
unknown-alloca origins now throw; provenance is computed before the legacy wire slice, which is
skipped when it cannot be formed (negative offset used to BoundsError). New
`test/test_jkf0_gep_provenance_composition.jl` 82 pass (8 shapes x N in {4,16} x fold on/off,
exhaustive Int8 vs a memory oracle, plus the F2 `.ll` and persistent cases); 39 related files
6725 pass. Gate counts unchanged. Left out: constant-index raw-alloca `VarGEP`, mixed-width
composition, element-width scaling (filed).
