**Bead:** `Bennett-r92o` / CW-D3 Lever 2 (BennettVM `416r.13` Bennett.jl side).
Design pre-decided — consensus doc `docs/design/Bennett-iwo9-CW-D3-typetag-consensus.md`

closed-world `ptr_cells=true` VM gate → a Symbol-callee `IRCall(:gc_alloc_obj,

### Operand-layout finding (empirical, before any edit)

`call ptr @julia.gc_alloc_obj(ptr %task, i64 %size, ptr %tag)` — raw LLVM walk
(hand-built `.ll`, `LLVM.operands(inst)`):
- `n_ops == 4`. Callee is the LAST operand (`ops[4]` name == `"julia.gc_alloc_obj"`),
  matching the existing `cname = LLVM.name(ops[n_ops])` convention.
- `ops[1]` = task (PointerType — the `%pgcstack` GEP; **DROP**), `ops[2]` = size
  (i64), `ops[3]` = tag (PointerType, the `%1` inttoptr dest). So 3 args ⇔ `n_ops==4`.
- The `.ll` MUST `declare ptr @julia.gc_alloc_obj(ptr, i64, ptr)` or LLVM rejects
  the call ("use of undefined value") — fixtures carry the declare line.

**SURPRISE vs the bead's stated assumption.** The bead said gc_alloc_obj "matches
the broad `julia.gc_` benign-prefix allowlist and is SILENTLY DROPPED (dest never
binds)". NOT what happens today. Under `ptr_cells=true` the **generic C-call arm**
(`instructions.jl` ~line 2198, `if ptr_cells && n_ops >= 1 … callee_val isa Function`)
catches gc_alloc_obj FIRST (before the benign-prefix check ~line 2321) and emits the
WRONG-shape IRCall: callee `Symbol("julia.gc_alloc_obj")` (full dotted name, not
`:gc_alloc_obj`) with the task arg CARRIED → 3 args `[task, size, tag]` widths
`[64,64,64]`. The benign `julia.gc_` drop only fires under `ptr_cells=false` (the
C-call arm is gated off). So the intercept had to go INSIDE the C-call arm, at its
top (right after the gc_preserve drop, before the generic arg loop), NOT merely
"before the benign-prefix check" — placing it only before benign-prefix would be
too late (the generic loop runs first).

### The arm (consensus decision 4)

`src/extract/instructions.jl`, inside `if callee_val isa LLVM.Function`, immediately
after the `gc_preserve_begin/_end` drop:
```julia
if cname == "julia.gc_alloc_obj"
    n_ops == 4 || _ir_error(inst, "... expected 3 args (task, size, tag) ⇒ n_ops==4 ... (Bennett-r92o / CW-D3 Lever 2)")
    size_op = _operand(ops[2], names)   # ops[1] (task) DROPPED
    tag_op  = _operand(ops[3], names)
    return IRCall(dest, :gc_alloc_obj, IROperand[size_op, tag_op], Int[64, 64], 64)
end
```
Rides the existing Symbol-callee `IRCall` constructor (Bennett-k3ej; `IRCall.callee
::Union{Function,Symbol}`) — NO new IRInst type. Fail-loud arity guard (CLAUDE.md §1).
Gate-off (`ptr_cells=false`): whole C-call arm skipped → broad `julia.gc_` benign
drop intact → circuit path byte-identical.

## Session log — 2026-06-23 — Bennett-iwo9 Lever 1: type-tag globals + ptrtoint/inttoptr

**Bead:** `Bennett-iwo9` / CW-D3 Lever 1. 3+1 design pre-decided in
`docs/design/Bennett-iwo9-CW-D3-typetag-consensus.md` (decisions 1–3 only).
Implementer role. Scope: under the closed-world `ptr_cells=true` VM gate,
recognise Julia type-tag globals (`@"+Type#N"`) BY NAME and model the cluster
`load @"+Type#N" → ptrtoint → inttoptr` soundly + deterministically. Out of
scope: gc_alloc_obj (Lever 2), any BennettVM change (Lever 3). RED-GREEN TDD.

### Research (empirical, before any code)

- **R1 — the EXACT pre-fix wall.** Captured from a hand-built `.ll`
  (`load ptr @"+Main.Base.Dict#148" → ptrtoint → inttoptr → ptrtoint → ret`):
  `ir_extract.jl: ptrtoint in @f:%top:   %d = ptrtoint ptr %tag to i64 — unsupported LLVM opcode`.
  The bead's "unsupported LLVM opcode" prediction was RIGHT; the analysis's
  "unbound-SSA / unknown operand ref" prediction was WRONG. The `ptrtoint`
  opcode is the first to error: it has no handler arm, so it falls straight
  through to the generic `_ir_error(inst, "unsupported LLVM opcode")` at the
  bottom of `_convert_instruction`. The tag `load` is processed first and is
  silently skipped (`return nothing` — its pointer operand is a GlobalVariable,
  not a registered SSA name), so its unbound dest never gets a chance to surface
  an "unknown operand ref" — `ptrtoint` walls first. **The message is
  byte-IDENTICAL under both `ptr_cells=true` and `ptr_cells=false` pre-fix** —
  ideal for the byte-identity assertion (GATE c).

- **R2 — instructions, not ConstantExprs.** Raw LLVM walk confirms `%d`/`%p`/
  `%d2` are all `LLVMInstructionValueKind` (`src isa LLVM.Instruction == true`),
  NOT folded ConstantExprs. So the `_convert_instruction` cast arm is the right
  edit site (not `_fold_constexpr_operand`).

- **R3 — global form + name.** The tag global parses cleanly as an external
  declaration: `@"+Main.Base.Dict#148" = external global ptr`. The load's
  pointer operand resolves directly to `LLVM.GlobalVariable`, and
  `LLVM.name(ptr) == "+Main.Base.Dict#148"` (the `+`-prefixed string preserved
  verbatim). No bitcast chase needed for the fixtures. Recognition is purely by
  name — we never touch the (non-deterministic JIT-address) initializer.

- **R6 (note-only, no edit):** `is_injective`/`is_l2_capable` live in BennettVM
  per-concrete-type history dispatch — confirmed via the consensus doc, not
  touched this cycle.

### Canonicalization scheme (consensus decision 1)

`_is_type_tag_global_name(s) = startswith(s,"+") && occursin(r"#\d+$", s)`.
`_canonical_type_path(gname)` strips the leading `+` and the trailing `#<digits>`
→ `"Main.Base.Dict"`. FAIL LOUD (CLAUDE.md §1) on a `+`-prefixed name lacking the
`#N` suffix (unexpected JIT naming). Both co-located near `_ptr_identity` in
`src/extract/constexpr.jl`. The `#N` suffix is the run-varying discriminator, so
`Dict#148` and `Dict#999` canonicalize identically → same interned id
(`#N`-invariance). Id minting: extraction-local `tag_ids::Dict{String,Int64}`,
dense first-seen walk order (`get!(tag_ids, canon) do Int64(length(tag_ids)) end`)
→ deterministic across re-extractions because the LLVM walk order is. NOT
persisted into ParsedIR (decision 2) — baked into emitted IR.

### Coordinator-review hardenings (2026-06-23, applied post-accept)

Two small hardenings requested at review, both applied + re-run green:

1. **Width guard on the ptrtoint/inttoptr arm (fail-loud completeness).** The
   arm previously emitted a width-64 `IRBinOp` unconditionally once `src ∈
   tag_ssa` — a type-tag cast to a NON-64-bit width (`ptrtoint ptr %tag to i32`)
   would silently emit a width-64 op for an i32 dest. Can't occur in the real
   fdict cluster (tags are always 64-bit round-trips) but a core arm must not
   hardcode an unverified width. Now, before the `return IRBinOp(...)`: compute
   `src_w` / `dst_w` (PointerType ⇒ 64, else `_iwidth`) and `_ir_error` with an
   iwo9/CW-D3 + width breadcrumb if either ≠ 64. New test GATE (b3)
   (`TAG_NARROW_WIDTH`: `ptrtoint ptr %tag to i32` under ptr_cells=true →
   `:err` with iwo9/CW-D3 + "64-bit"/"width") proves it.

2. **Removed dead "recognized-but-unminted" guard in the load arm.** The
   `haskey(tag_ids, canon) || _ir_error(...)` sat right after the `get!(tag_ids,
   canon) do ... end` that ALWAYS inserts `canon` → `haskey` was always true,
   the `_ir_error` unreachable. Deleted; the "no silent fall-through" protection
   is the `return IRBinOp(...)` itself (a tag-named-global load always emits the
   minted identity, never reaches the generic IRLoad). Comment rewritten to stop
   claiming a guard that wasn't there (the only fail-loud on this path is
   `_canonical_type_path`'s malformed-`+`-name error).

Re-run after both hardenings (one julia at a time, --check-bounds=yes):
`test_iwo9_typetag.jl` 30/30 (27 prior + 3 new b3 assertions), gate-count 39/39,
zf5v 17/17. No regression.
