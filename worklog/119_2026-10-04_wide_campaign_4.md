**Bennett-sl4h, hybrid step — bead stays OPEN (P1).** With `bit_width=W`, `optimize=true` and
W ≠ S, `_narrow_hybrid` (`src/extract/callees.jl`) narrows the unoptimised IR first — the same
circuit as `optimize=false`, sound by construction — and falls back to the optimised IR + koi8
checks only when that attempt is refused. At W == S the optimised path is used directly (nothing
is re-typed). Landing logs (rebased tree): sl4h 79 + 1 broken (the intended pin), koi8 31, 6p8j 599,
g7d6 298, mrhg 212,916, gate baselines 39.
- What triggers the fallback: `ArgumentError` (every narrowing refusal) and ANY `ErrorException`.
  `_ir_error` and the extractor's roughly 180 raw `error()` refusals are both plain
  `ErrorException`, so a deliberate refusal cannot be told from an accident without matching
  message text. `MethodError`, `BoundsError`, `KeyError`, `AssertionError`, `InterruptException`
  propagate. (A typed refusal exception for the extractor would remove that ambiguity.)
- koi8 corpus, `optimize=true`, W < 8: 593 accepted / 1183 refused → 760 / 1016, 0 lost, 0
  accepted-and-wrong. Of the 760, 223 come from the unoptimised IR (gates identical to
  `optimize=false`), 537 from the fallback. No narrowed gate-count pin moved.
- Pins that became "accepted and right": koi8 `x * 16 == 0` @ W=6 (`@test_broken` → `@test`),
  `k8_signbit` @ W=7, 6p8j `p6_band` @ W=6, g7d6 `g7d6_sw` @ W=4. The old refusal coverage is kept
  by calling `_narrow_ir(...; optimized=true)` directly on the optimised IR.
- **The remaining hole is ordinary code**, pinned `@test_broken` at
  `test/test_sl4h_narrow_unoptimised.jl:301`: `(x == 5) | (x * Int8(16) == Int8(0))` @ W=6 is wrong
  on 12 of 64 inputs; `Int8(x * Int8(16) == 0)` alone — an untyped `0` — is wrong at W = 5, 6, 7;
  UInt8 `(x > 2) | (x * 0x10 == 0x00)` is wrong at W = 5. Every wrong case found has a REFUSED
  unoptimised IR: the untyped literal promotes `x` to i64 (`sext i8 → i64`, `icmp … i64`), which
  the allowlist rejects as a second data domain, so the compile falls back.
- Even the common idioms (`x == 5`, `iseven`, UInt8 `x > 2`, `Int8(x == 5 ? 1 : 0)`) compile via
  the FALLBACK; only `x >> 1` @ W=7 uses the unoptimised IR. So the sound path is taken by a
  minority of real programs until the allowlist learns the promotion idiom — step (a), now running
  in `s5`: an extension iS → iN whose only uses are a compare against a fitting constant (or
  another such extension) or a trunc back to iS.
- The parsed-IR cache holds 256 entries and a corpus test overflows it, so `===` identity of a
  `ParsedIR` across two compiles is flaky under eviction; compare gates in corpus tests.
