### What landed
- **D1** (`src/ir_types.jl`): `IRCall.callee` widened `Function` →
  `Union{Function,Symbol}`. A `.ll` callee has only a name; BVM consumes
  callees by name already, so no `IRCallByName` fork (Law 2). Added a
  Symbol-callee inner-constructor overload mirroring the Function one
  (same validations). Function inner constructor is **byte-identical** —
  it still uses `nameof(callee)` directly (typed `::Function`). New
  `_callee_name(::Function)=nameof` / `(::Symbol)=identity` helper names
  the callee in the Symbol path's diagnostics.
- **D2** (`src/extract/module_walk.jl` + `helpers.jl`): a `ptr` param with
  NO `dereferenceable(N)` (the C heap-pointer case) now becomes an opaque
  Int64 cell-address arg (width 64) instead of being silently skipped.
  Gated to `deref == 0` so the Julia NTuple-by-ref/sret model (`deref>0`)
  is untouched.

### The non-obvious bit — the real wall was the clang comment line
`_get_deref_bytes`'s text fallback hardcoded `defline = split(...)[1]`.
On a **C/clang** `.ll`, `string(func)` line 1 is the `; Function Attrs: ...`
COMMENT, not the `define`. So the fallback found no `(...)` and threw the
"malformed define" AssertionError on **every** C function — THAT was the
ptr-parameter wall, not a deref-value bug. (The primary
`LLVM.parameter_attributes(func,idx)` API path MethodErrors on this
LLVM.jl version, so the text fallback always runs for these.) Fix:
`findfirst` the actual `define`/`declare` line. Rule 5/8-clean: not
extending the parser, just reading the right line.
