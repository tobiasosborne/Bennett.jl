## Blocking issues

- **[codex] B1_LLVM_DEFINEDNESS** (§§0, 3.2–3.3, 4.2, 8 rung 7): “Undefined behaviour is concretised and recorded” is false for the stated optimise-first pipeline. LLVM UB is not a random environmental choice: optimisation may remove or change behavior before the offending operation, leaving nothing a link-time recorder can reconstruct. Undef, poison, freeze, and external nondeterminism are also distinct concepts. This matters particularly for a kernel-fuzzing oracle: agreement with the same optimised native binary cannot establish the promised semantics of executions affected by source UB. [LLVM UB manual](https://llvm.org/docs/UndefinedBehavior.html) *Fix:* State that correctness applies under explicit definedness assumptions covering every basis input in the supported coherent domain. Distinguish deterministic refinements of permitted undefined values from immediate UB and poison-triggered UB. If faulting executions are supported, establish defined checked or machine-simulation semantics before optimisations exploit UB. Record these assumptions and any fixed environmental choices in the certificate.
- **[codex] B2_SOURCE_MARKER_ABI** (§§3.1 qubit handles, 3.3, 6.1 dialect specification): The dialect requires dedicated-address-space pointer handles, while the Rust integration merely exports bitcode from unmodified rustc. Rustc's internal LLVM bindings are not an extension point available to an ordinary Rust marker library; emitting bitcode does not let that library choose arbitrary pointer address spaces. Consequently, the proposed universal source ABI lacks a supported Rust emission path. Address-space meanings are also target-dependent. [Rust pointer types](https://doc.rust-lang.org/reference/types/pointer.html), [Clang address-space attribute](https://clang.llvm.org/docs/AttributeReference.html#address-space) *Fix:* Define a portable source marker ABI using ordinary opaque pointers or integer handles, with Bennett normalising recognised handles into its internal representation. Specify how that representation respects the incoming target's pointer layout and address spaces. Gate the dialect specification on actual clang, Rust, and Julia emission examples, as well as optimisation tests.
- **[codex] B3_BOUND_EXHAUSTION** (§§3.1 bounds, 4.2, 5.1, 9.4): Forcing a predicate permanently false does not distinguish normal termination from exhaustion while computation remains active. It can silently produce a truncated result that differs from native execution, even when the resulting circuit is reversible and cleans its workspace. Deferring this distinction permits the VM and specialiser to implement different functions. Recursion and workspace exhaustion require the same treatment. *Fix:* Choose a shared semantic rule: require bounds sufficient for all supported inputs under stated assumptions, or define a total bounded computation with a reversible exhaustion flag and specified output behavior. Preserve enough state to uncompute, expose failure only through the declared interface, and identify whether the reference oracle is the original function or its explicitly bounded variant.
- **[codex] B4_VERIFICATION_SCOPE** (§§4.2, 5.1, 8, 9.6): The permutation theorem does not make property-based testing complete: untested basis inputs can still be wrong. Its stated XOR embedding also requires checking the full allowed domain, including arbitrary target-register contents, input preservation, and dirty-borrow restoration. Measurement-based uncomputation is a channel implementation, not generally a unitary on the measured system; checking selected state-vector trajectories is insufficient to establish its behavior on entangled inputs. A record of test seeds cannot upgrade these checks into a universal correctness proof. [Quantum-channel representations and equivalence](https://learning.quantum.ibm.com/course/general-formulation-of-quantum-information/quantum-channels) *Fix:* Keep the permutation theorem, but label exhaustive checks complete only for their declared finite domain and sampled checks as evidence. State the full input/output relation, including dirty registers. For measurement-assisted implementations, compare the induced channel, or instrument when outcomes are exposed, including controlled execution and reference-system correlations. Distinguish replayable validation records from independently checkable proofs, and specify the scope and composition of approximation budgets.
- **[muse] B1_CORRECTNESS_COMPLETENESS** (5.1, 1 decision 7, 8 rungs 4/7/8): Section 5.1 correctly observes that an ideal circuit using only X, CX, CCX and exact MCX is a permutation, but then calls testing 'exhaustive at small widths and property-based above' complete. Property-based sampling over a proper subset of basis inputs cannot determine the permutation on unsampled inputs; it is evidence, not completeness. The document also does not state that the theorem must be applied after MCX decomposition: a relative-phase Toffoli decomposition is not a permutation matrix and can introduce phases invisible to basis tests, while measurement-based cleanups likewise leave the permutation tier. Finally, checking only ancillae initialized to zero proves the action on that clean-ancilla subspace, not correctness under dirty borrowing or other ancilla domains unless those are separately included. *Fix:* Restate the theorem with its exact domain: exhaustive agreement over all x and target values, with ancillae initially in the stated clean state, determines the oracle on that subspace. Define the permutation tier after decomposition into the gates actually emitted, excluding relative-phase Toffoli/MCX decompositions and measurement fixups from that tier. Label sampled differential testing as evidence, exhaustive testing or a compositional/structural proof as proof, and make the certificate distinguish those cases and state the input/ancilla domain proved.
- **[muse] B2_BOUND_EXHAUSTION_SEMANTICS** (4.2, 9.4, 0, 8): The padded semantics say what happens before a bound is reached, but not what a branch that would exceed its loop, recursion, allocation or execution bound means. Section 9.4 defers this and says only that 'a predicate that is false forever is the only legal outcome.' If the remaining body is merely predicated off, execution after the loop can proceed from a truncated intermediate state and produce a branch-dependent wrong oracle result, with no coherent trap possible inside the region. That contradicts section 0's promise of never a silent wrong answer and leaves SQLite/kernel resource estimates unable to distinguish a valid large instance from one whose assumed bound truncates some branches. The source of bounds for the many internal data-dependent loops in unmodified code is also still only implicit. *Fix:* Define bound exhaustion in section 4.2 itself: exceeding a loop, recursion, allocation or step bound in any branch sets an explicit overflow outcome in the region result/certificate, makes the region result invalid rather than an oracle result, and is checked in differential tests and resource estimates. State who supplies the region-level classical bound or step budget from which internal bounds for unmodified code are derived.
- **[opus] B1-coherent-totality-and-bounds** (§3.1 bounds row, §4.2, §4.5, §5.1, §8 rungs 4/7/8, §9.4): Coherent execution of unmodified programs is not yet defined, in three linked ways. (i) The only stated bound mechanism is a per-loop `__bennett_bound` operand 'consumed by the loop's guard', with a compile error otherwise. That needs source edits in SQLite, Linux and the Monte Carlo, contradicting 'nobody rewrote SQLite'. It also relies on loop identity surviving O3 (rotate, unswitch, versioning, unroll, vectorise), which it does not. Read literally as an LLVM `token`, a non-intrinsic function cannot return it. (ii) Coherent control is specified only through structured pred{} and loop{}. Post-O3 CFGs of these programs are unstructured or irreducible: VDBE dispatch, gotos, recursion, and indirect calls on superposed pointers. The general construction is unstated. (iii) Some basis branches will exhaust the bound, trap, hit immediate undefined behaviour, or touch an unvirtualised device inside the region. None of these has a defined output, so the oracle is not a total function and §5.1's permutation theorem has nothing to compare against. In addition, 'undefined values are concretised at entry' is false for poison computed from superposed data. Uncorrected, the project builds a per-loop-annotated dialect that cannot compile the flagship rungs, and oracles whose behaviour off the happy path is silently truncated rather than failing loud. *Fix:* (a) Make the primary bound a region-level classical budget: dynamic steps, plus heap and recursion depth. It is passed as an ordinary integer operand of `__bennett_ctrl`/region entry, or supplied out of band by the host or driver, and applied by the plugin after outlining, so no loop identity has to survive optimisation. Per-loop SCEV and marker bounds become refinements. (b) Define coherent execution of an arbitrary CFG as a predicated step machine: a superposed block counter stepped for the budget, with structured pred/loop as optimisations of it. Both executors share this semantics. (c) Make every coherent region total by construction. Each region gets a fault/exhaustion output register, with a distinct code per cause (budget, trap/UB, unmodelled effect), as part of the oracle's output. Define poison/undef as a fixed deterministic refinement of the region's inputs (freeze). (d) Restate §5.1 equivalence as 'equals native, or is flagged'. Require each rung to report the flag rate over its tested domain, and require that rate to be zero for the acceptance instances.

## codex

The direction is sound, but four semantic or interface corrections remain blocking. Round-1 status: codex B1_EFFECT_DOMAINS and muse B4 are partially resolved—the external-effect boundary is fixed, while definedness remains B1; opus B4 is resolved. Codex B2_LLVM_CONTRACT, muse B1, and opus B1 have their intrinsic, type-linearity, metadata, and lifetime issues resolved, but the replacement frontend ABI retains B2. Muse B2 and opus B3 have their driver and whole-program compilation issues resolved, with the Rust ABI qualification in B2. Opus B2 is resolved by reference-to-wire staging. Codex B3_COHERENT_RUNTIME and muse B3 have their control and scheduling issues resolved, but bound-exhaustion semantics remain B3. Codex B4_QUANTUM_CORRECTNESS and muse B5 are partially resolved and remain B4. Muse B6 and opus B5 are resolved at vision level by the expanded ISA contract and shared scheduler component. The editor's branch-enumeration premise is correct for a genuine permutation oracle with restored workspace; it does not extend to arbitrary coherent regions or independently validate their physical lowerings.

- **C1 4**: The LLVM front door, reversible oracle construction, resource-aware ISA, and two executors describe one ambitious system. The closed-effect boundary makes the SQLite and kernel demonstrations coherent, but undefined behavior and bound exhaustion still lack consistent correctness contracts. *Change:* Make the defined execution domain and bound-failure behavior explicit qualifications of the thesis.
- **C2 3**: Declared markers, explicit bound operands, reference-to-wire conversion, and whole-program transformation are credible mechanisms. The remaining claims about concretising LLVM undefined behavior, Rust address-space emission, and the sufficiency of negative call attributes are incorrect or overstated. *Change:* Replace those claims with a definedness contract, a portable source marker ABI, and positive requirements for marker effects.
- **C3 4**: Sections 4.2–4.4 clearly distinguish dynamic classical control from padded coherent control and identify allocation, garbage, resources, and launch semantics. However, a permanently false predicate does not specify a correct response when a live branch exhausts its bound. *Change:* Specify bound exhaustion as either an excluded execution under an explicit precondition or a reversible, observable error outcome.
- **C4 4**: The ISA now owns the object format, reversible ABI, launch ABI, and certificate schema; independent executors share a specification rather than requiring shared implementation. The scheduler C ABI and driver invocation interfaces still need explicit ownership within the claimed two-contract structure. *Change:* Assign every callable cross-repository interface to a published contract, including scheduler and driver interfaces.
- **C5 4**: Whole-program bitcode, an owned driver, host-triple lowering, and named frontend integrations make the no-fork strategy credible. Requiring dedicated-address-space handles directly from unmodified Rust remains an unsupported frontend assumption. *Change:* Accept source-emittable marker signatures and perform any required handle normalisation in Bennett's pipeline.
- **C6 2**: The permutation theorem is correct under exhaustive agreement on the complete declared input domain, and permutation-oracle branch enumeration is sound. Section 5.1 nevertheless calls sampled testing complete and specifies unitary equivalence for measurement-bearing implementations without defining their channel or instrument semantics. *Change:* Separate mathematical correctness, exhaustive finite-domain checks, sampled evidence, and measurement-channel verification in both acceptance criteria and certificates.
- **C7 4**: The landscape table identifies relevant predecessors and mostly claims a combination rather than inventing its ingredients. Section 4.1's assertion that quantum programming has lacked an abstraction layer is historically false: Quil already specifies a portable quantum abstract machine. [Quil specification](https://quil-lang.github.io/) *Change:* Add Quil/QAM and eQASM, and describe the missing combination of reversible compilation, lifecycle semantics, and resource scheduling.
- **C8 4**: The architecture, component ownership, and concrete demonstrations give the three intended readers useful direction. Some semantic obligations remain under open technical questions despite determining what programs mean and what successful verification establishes. *Change:* Move definedness, bound failure, and verification scope into normative decisions; defer their implementation mechanisms.

Suggestions:
1. Tighten §3.1's call-legality wording. Absence of readnone and speculatable is insufficient: a readonly, returning call can still be eliminated or commoned. Conservative external effectful declarations are a viable foundation; specify their positive effect requirements and prohibit incompatible attributes. [LLVM memory attributes](https://llvm.org/docs/LangRef.html#function-attributes)
2. Publish ownership of the scheduler C ABI and driver invocation interface. Also reconcile §6's claim that every Rust component consumes ISA serialisation with the driver's stated bitcode responsibilities; invoking LLVM tools externally is a coherent arrangement.
3. Explicitly restrict branch enumeration to permutation blocks, or to logical permutation abstractions whose lowerings are separately verified. Enumerating the compiled permutation on each supported basis component is exact and can avoid a state vector spanning SQLite's workspace; arbitrary rotations and measurements need additional simulation machinery.
4. State that classical scheduling decisions do not authorise copying arbitrary quantum checkpoints. Checkpoint and recomputation operations must themselves preserve quantum state and correlations.
5. Strengthen rungs 2, 3, and 6 with independent forward-result checks. Byte-exact reversal and deterministic tape replay alone can certify an implementation that consistently computes the wrong forward result.
6. Clarify that an exact-synthesis witness demonstrates attainability; claimed minimality additionally needs a checkable lower-bound or exhaustive-search certificate.
7. Replace the historical absence-of-abstraction argument with a precise comparison to Quil/QAM and eQASM. These predecessors do not invalidate Bennett's proposed combination. [Quil specification](https://quil-lang.github.io/), [eQASM paper](https://arxiv.org/abs/1808.02449)

## muse

Round 1 status: codex B1 is resolved by sections 0 and 4.2; codex B2 is resolved by the section 3.1 rewrite; codex B3 is mostly resolved by the classical-only runtime-policy invariant and padded coherent semantics, but its bound-exhaustion subpart is not resolved and is re-raised; codex B4 is partly resolved by the new phase-sensitive tiers, but the sampled-testing completeness claim remains and is re-raised. Muse B1, B2, B3 and B4 are resolved; muse B5 shares the unresolved completeness/certificate subpart; muse B6 is resolved at vision level, with only the bennett-sched ABI ownership left as a suggestion. Opus B1, B2, B3, B4 and B5 are resolved, subject to that same sched-interface suggestion. The editor's branch-enumeration claim is correct for a permutation oracle when the full output basis configuration is tracked, but it should be scoped to permutation segments rather than arbitrary coherent regions containing non-permutation gates. The revised document is now a coherent and unusually strong founding vision, but two narrow semantic corrections are still required before it can be accepted.

- **C1 4**: The thesis is now precisely qualified in section 0, and sections 4.2, 5.1 and 8 describe the same closed coherent tier rather than unrestricted controlled-anything. The remaining incoherence is that section 3.1 makes a missing coherent-loop bound a compile error while rungs 4, 7 and 8 promise unmodified SQLite, Linux and Monte Carlo code. *Change:* State the region-level bound/step-budget mechanism that makes unmodified data-dependent code effect-bounded without per-loop source annotations.
- **C2 4**: Section 3.1 now uses declared marker functions, handle pointers, analysis-derived taint, bounds as operands and liveness, and explicitly withdraws plugin-registered intrinsics, target extension types, loop metadata and lifetime intrinsics. Residual simplifications include the portability of a dedicated address space across host targets and the description of taint as only a forward dataflow. *Change:* Add codegen and target-address-space cases to the legality spike and replace forward-only taint with context-sensitive data, control and memory dependence.
- **C3 4**: Section 4.2 now separates classical instruction-pointer control from predicated, padded coherent control, forbids runtime policy from inspecting superposed data, and sections 4.2-4.3 state honest costs for both branch arms, padded allocation and O(N) quantum-addressed memory. Bound exhaustion remains deferred to section 9.4 despite being part of the core padded semantics. *Change:* Define bound-exhaustion/overflow semantics and its interaction with histories and clean release in the ISA vision.
- **C4 4**: Section 4.4 makes the ISA spec own the reversible ABI, link format, launch ABI and cost-certificate schema, and section 6.1 withdraws the shared-executor-codebase claim in favour of the formal model and conformance suite. The shared bennett-sched binary linked by plugin and executors is nevertheless an interface not assigned to either named contract. *Change:* Say whether the bennett-sched C ABI and cost semantics are owned by the ISA spec or are a third internal contract.
- **C5 4**: Section 3.3 credibly moves the plugin to link-time whole-program bitcode, owns the driver and fat-object format, accepts host-triple IR, and names clang, rustc and Julia integration separately. It still understates that obtaining bitcode for Rust std, Julia runtime code and precompiled native libraries may require special builds or shims rather than ordinary unmodified front-end use. *Change:* State availability limits for whole-program bitcode for language runtimes and standard libraries as explicit coverage constraints.
- **C6 3**: Section 8 now gives every rung instance sizes, oracle checks and resource-estimate requirements, and section 5.1 correctly adds phase-sensitive checks for non-permutation lowerings with an epsilon budget. But section 5.1 still calls property-based testing above exhaustive widths complete, which is mathematically false and makes the meaning of a certificate ambiguous. *Change:* Correct section 5.1 so sampled differential testing is evidence and only exhaustive or compositional proof is called complete/proof-carrying.
- **C7 4**: Section 7 now covers Enzyme, PTX/offload, QIR, OpenQASM 3, Quake, Catalyst, Q#, Quipper, Silq/Unqomp/Reqomp/SQUARE, Tower, Qualtran/Azure RE, QSSA/QIRO, ReVerC and the pebbling literature, and narrows novelty to inferred-taint reversibilisation plus the public virtual ISA and shared compile/run-time scheduler. The QIR criticism is now precise and acknowledges dataflow participation and newer profiles. *Change:* Qualify the catalyst and taint-novelty wording against Enzyme activity analysis and MLIR lowering paths, while keeping the narrow combination claim.
- **C8 4**: Sections 3.1, 4.4, 4.5, 6.1 and 8 give a compiler engineer, hardware vendor and language designer concrete surfaces, repository dependencies and acceptance tests. Two load-bearing semantic points remain deferred or misstated: what happens when a classical bound is exceeded and what part of a proof-carrying certificate is actually proof. *Change:* Move bound-exhaustion semantics and certificate proof-versus-evidence labels from deferred questions into sections 4.2 and 5.1.

Suggestions:
1. Put the bennett-sched C ABI, objective semantics and versioning in bennett-isa-spec, or explicitly name it as a third internal contract; otherwise a competitor VM can conform to the ISA while invalidating compile-time schedules and certificates.
2. Scope branch enumeration exactly: it is exact for permutation segments and for sparse simulation only while the full branch configuration, including garbage and virtualised device state, is tracked; non-permutation gates between such segments must be applied to amplitudes and can increase branch count.
3. Replace 'forward dataflow' taint with context-sensitive interprocedural analysis over data dependence, control dependence and memory effects, with polyvariant specialisation when one function is used both classically and coherently.
4. Define LLVM poison/undef handling separately from source UB: state where freeze/concretisation occurs relative to optimisation and what per-branch traps such as division by zero or invalid shifts become inside a coherent region.
5. Extend the legality spike beyond O3 IR passes to native code generation for fat objects containing handle address-space values, including targets that already reserve nearby address-space numbers.
6. Clarify the VM-versus-circuits hardware-lowering boundary: which component lowers predicated ISA blocks to a target gate alphabet at launch time, and what capabilities beyond costs a target description must declare.
7. Correct minor wording that stock passes may inline marker calls: an external declaration cannot itself be inlined, although containing functions may be inlined, cloned or unrolled.

## opus

Iteration 2 is a substantial and mostly correct revision. Status of round-1 blocking issues: codex B2, muse B1, opus B1 (extension points): resolved; marker calls, address-space handles, taint by analysis and the legality spike are sound, with small residues (the token return, PipelineStartEP versus link time, the rustc 'bindings' wording) moved to C2 and the suggestions. muse B2 and opus B3 (compilation model): resolved by link-time whole-program bitcode, fat objects, and our own driver. codex B1, muse B4, opus B4 (effects): resolved by the per-tier effect table and the closed, effect-free coherent tier; one residue, undefined behaviour inside regions, moves into new B1. muse B3 (control classes): resolved; one residue, unstructured CFGs, moves into new B1. codex B3 (coherent runtime): the classical-only invariant and the clean-release obligations are resolved, but bound-exhaustion semantics are still deferred and re-raised in B1. codex B4 and muse B5 (phase-blind correctness): resolved. The permutation theorem is correct, provided the basis inputs include the target and dirty-ancilla values, and non-permutation lowerings get unitary and interference checks. opus B2 (qubit value versus reference semantics): resolved, with reference semantics in the dialect and wire form in the ISA. muse B6 and opus B5 (repository split): resolved, except that the bennett-sched C ABI is an unenumerated third contract (a suggestion). One new blocking issue remains, and it sits at the heart of the thesis. The dialect's only bound mechanism, a per-loop marker operand, needs source modification and loop identity that O3 destroys. The ISA sketches only structured coherent control. And nothing defines what a coherent branch produces when it exhausts its bound or faults. So the flagship 'unmodified SQLite/Linux' rungs do not follow from the design, and the oracles are not total functions for the correctness theorem to apply to. With region-level bounds supplied out of band, a predicated step machine as the general coherent semantics, and a fault/exhaustion output that is part of every oracle, the document would be close to founding-document quality.

A monolith core is still hiding. `bennett-sched` is linked as a binary by both the plugin and the VM through a C ABI that is not part of either contract (§9.8 defers 'the bennett-sched interface'). The plugin↔driver and driver↔Bennett.jl interfaces are unenumerated as well. Scope branch enumeration to permutation regions. Define equivalence as 'native result, or a flagged fault/exhaustion that is reported and must be zero on the rung's tested domain'.

It also never says whether `__bennett_ctrl`/`__bennett_adj` regions may contain user measurements, non-released allocations, or effects. *Change:* Add a short well-formedness rule for control/adjoint regions: unitary only, with user measurement refused (or deferred by the deferred-measurement principle, stated as such) and the compiler's measurement-based uncomputation the sole exception. Also say how a program enters the reversible tier.

Suggestions:
1. Make the `bennett-sched` interface (scheduling problem in, schedule and certificate out) a section of `bennett-isa-spec`, and name the driver's plugin-invocation and coverage-report formats. Otherwise 'two contracts, fully enumerated' and 'every repository replaceable' are not true for the scheduler.
2. Add well-formedness rules for `__bennett_ctrl`/`__bennett_adj`/`__bennett_compute` regions. They must be unitary. User measurement inside them is either refused or deferred by the deferred-measurement principle, stated explicitly. Allocations must be released clean or borrowed and restored. The compiler's measurement-based uncomputation is the sole exception, with its controlled form defined (§9.6).
3. State which call-site attributes, if any, the plugin adds to gate markers, and when, given §3.3's link-time model. Note the hazard: if gate calls are marked as touching only inaccessible memory, GVN and store-to-load forwarding can reorder or forward quantum-address-space loads and stores across gates on the same qubits. Add this to the legality corpus.
4. Allow handles to arrive in addrspace(0) from front ends that cannot name address spaces in source (Rust), with retyping at link time. Add a fail-loud check that no quantum-address-space access survives into host native code.
5. Scope the branch-enumeration claim (§4.2, §5.1 part 3) to permutation regions. A region that contains H, rotations, or measurement-based uncomputation needs state-vector or stabiliser simulation instead.
