## Blocking issues

- **[codex] B1_LLVM_DEFINEDNESS** (§§0, 3.2, 4.2, 5.1 and 8 rung 7): Section 3.2 acknowledges that optimisation can erase source UB, but §0 still promises named faults for executions outside the defined domain. These cannot both hold for source executions. I confirmed locally that clang -O3 turns `int f(int x){int y=10/x;return 0;}` into `return 0`, leaving nothing to fault on at x=0. UBSan also detects selected UB classes; a clean run does not establish source definedness. See the [LLVM UB manual](https://llvm.org/docs/UndefinedBehavior.html) and [UBSan documentation](https://clang.llvm.org/docs/UndefinedBehaviorSanitizer.html). *Fix:* Prefer the minimal correction: state that source equivalence requires an independently stated definedness assumption for every supported basis input; faults cover conditions encountered by Bennett's totalised optimised-IR machine, with no guarantee of detecting source UB erased earlier. Describe UBSan as supplementary evidence, not a complete domain classifier. Alternatively, retain source-level fault guarantees by introducing checked semantics before UB-exploiting optimisation, explicitly naming their coverage. The kernel rung must identify which contract it uses.
- **[codex] B3_FAULT_RESULT_SEMANTICS** (§§4.2 and 5.1): Saying that faulted outputs are 'not an oracle value' does not specify their quantum state. Two implementations can return the same fault code and clean workspace while one writes zero to the payload and the other copies x. On a superposition these produce different correlations, even if nobody reads the invalid payload. Comparing only the fault code therefore cannot establish the claimed common semantics. *Fix:* Define a deterministic bounded result F_B(x): success returns (f(x), 0), while failure returns (0, error_B(x)); implement it by XOR into payload and error targets, preserving the input and restoring workspace. Error selection must follow the shared bounded reference semantics. Alternatively, specify a deterministic partial-result payload on failure and compare it completely; I would choose the canonical zero payload. Merely disabling forward predicates is insufficient without retaining and reversing the required history.
- **[codex] B4_INPUT_PRESERVATION** (§5.1 part 1 and its conformance requirements): The theorem's listed hypotheses check the result and clean/dirty ancilla restoration, but do not require preservation of x. Appending X on an input bit after an otherwise correct oracle preserves every listed result and ancilla check, yet violates the claimed mapping. Exhausting target and dirty-register values does not close this hole. *Fix:* Require explicit equality of the entire register tuple: preserved input and reference state, target XOR the specified bounded result, correctly transformed fault target, unchanged dirty registers, and restored clean workspace. State input preservation in both the theorem's hypotheses and the acceptance checks; native execution supplies f(x), while the embedding specification supplies the complete expected state.
- **[opus] B1_QUANTUM_STATE_WRITE_SEMANTICS** (§3.1 (qload/qstore, ctrl regions), §4.2, §5.1 part 1): The document defines a coherent region only as an out-of-place oracle: |x⟩|t⟩|a⟩ ↦ |x⟩|t⊕f(x)⟩|a⟩, with workspace returned clean. It never says what classical code does to quantum state that outlives the region. Three cases are open. (a) What `__bennett_qload` from a handle means under linear ISA semantics: a move, or an entangling copy. (b) What `__bennett_qstore` into a handle whose contents are already superposed means. Overwriting is not unitary: the old value becomes garbage that cannot be uncomputed without an inverse. (c) How an in-place update x ← g(x) of a quantum register by classical code is compiled. This is the project's founding use case: Sturm's `when(q) do f(x) end`, controlled modular addition and multiplication in Shor. Uncorrected, the plugin must guess. It will either silently leave entangled garbage, which violates the region well-formedness the document requires, or support only out-of-place oracles while the thesis promises "controlled-anything". *Fix:* Add a "coherent memory and region interface" paragraph to §4.2 and mirror it in the dialect spec. (1) qload is a CNOT copy of the register onto fresh wires; the source is preserved and the copy is workspace. (2) qstore XORs into its target, so storing into a clean register is a copy. Storing into a register not known to be clean is a compile-time error, not a fault. (3) Region inputs are preserved, declared outputs are XORed into caller-supplied targets, and every other write is restored workspace. (4) In-place update needs an inverse. Option (a): a marker `__bennett_inplace(@g, @ginv, …)` lowered as compute g out of place, swap, then uncompute with g⁻¹; library primitives that are known bijections (add a constant, xor, rotate) carry their inverses in bennett-arith. Option (b): no in-place marker; front ends compose two compute regions and a swap. I would take (a), keeping (b) legal, because (a) makes `when(q) do x += a end` work as written. Either way, an in-place update with no inverse fails loud at compile time.
- **[opus] B2_UNCOMPUTATION_VALIDITY** (§3.1 (garbage row), §4.2 (classical control: pebbling policy), §4.3, §4.4 (scheduling interface)): Garbage is presented as pure scheduling policy: "the scheduler decides when to pay to free a dead value", run-time pebbling over the resource vector, and the run-time policy is constrained only to inspect classical data. Uncomputing garbage by reversing or recomputing its computation is correct only if every value it was computed from is in the same basis state at uncompute time as at compute time. Equivalently, no non-permutation gate (H, rotations other than diagonal ones, measurement) and no in-place update may touch those sources in between. This is Silq's qfree/const condition and Unqomp's validity criterion. Garbage still entangled with a qubit when that qubit is interfered also destroys the interference. A scheduler that defers uncomputation past such an operation, which this document licenses, computes the wrong state while every ancilla still returns to zero. *Fix:* State the invariant in the ISA formal model (§4.2/§4.4). Each garbage value records its dependency set. It may be uncomputed by reversal or recomputation only while that set is unmodified since its computation, and it must be cleaned before any non-permutation operation acts on a wire in its dependency set, and before the end of the enclosing unitary region. Measurement-based uncomputation with phase fixup is the sanctioned alternative where that window has closed. Compile-time and run-time schedulers choose only among schedules that satisfy this constraint. The handle→wire verifier (§9.2) rejects violations, and conformance tests exercise them with interference (§5.1 part 2). Credit Silq/Unqomp for the condition in §7.

## codex

The architecture is ambitious and substantially coherent. Round-2 status: codex B2_SOURCE_MARKER_ABI is resolved. Codex B1_LLVM_DEFINEDNESS is partially resolved, with the source-level guarantee still inconsistent. Codex B3_BOUND_EXHAUSTION and muse B2_BOUND_EXHAUSTION_SEMANTICS resolve budget sourcing and silent truncation, but leave fault payload semantics incomplete. Codex B4_VERIFICATION_SCOPE and muse B1_CORRECTNESS_COMPLETENESS resolve sampling, decomposition and channel-scope objections, but still omit explicit input preservation. Opus B1-coherent-totality-and-bounds resolves region budgets and arbitrary-CFG execution; its definedness and total-result aspects remain partial. These are narrow semantic corrections to a credible founding vision, not objections to its ambition or implementation status.

**Path to accept:** Three normative edits suffice: consistently limit UB guarantees to the chosen reference semantics and explicit definedness assumptions; specify the complete faulted output state; and require input preservation plus full-state comparison in the permutation theorem and conformance checks. No implementation or additional demonstration is required for acceptance.

- **C1 4**: The inferred tiers, virtual ISA, shared scheduler and two executors now describe one coherent architecture. The thesis still promises fault detection beyond what the optimise-first pipeline guarantees. *Change:* Make the thesis use exactly the definedness and fault contract adopted in §3.2.
- **C2 3**: Effectful external markers and the Enzyme-style link-time transformation are credible without an LLVM fork. The remaining UB guarantee is overstated, and the claim that Rust's distributed standard library lacks bitcode is false. *Change:* State the precise boundary between source-definedness assumptions and faults detectable in the selected optimised-IR reference machine.
- **C3 4**: The predicated step machine, classical-only scheduling policy, allocation classes and explicit padding costs make the VM proposal technically coherent. Unspecified fault payloads still prevent the two executors from implementing one fully determined coherent operation. *Change:* Define the complete reversible result on faulted inputs, including payload and preserved state.
- **C4 5**: Sections 4.4 and 6.1 now assign the object, linking, launch, scheduling, target and certificate interfaces to published contracts. Reusing a scheduler through its specified ABI is intentional modularity, not a hidden monolith. *Change:* None required at vision level; preserve these ownership boundaries during design.
- **C5 4**: Portable handles, explicit runtime coverage constraints and real frontend-emission gates resolve the previous source-ABI problem. The mixed-version rule still treats compatibility as more automatic than the toolchains promise. *Change:* Replace 'merge and run on the newest' with a tested compatibility envelope covering bitcode readers, target layouts, ABIs and frontend-specific IR.
- **C6 4**: The proof/evidence distinction, post-decomposition permutation boundary and channel comparisons are substantial corrections. However, §5.1's theorem still omits input preservation from its hypotheses and permits incomplete comparisons on faulted inputs. *Change:* Make the complete register-state relation the explicit object of verification.
- **C7 4**: The novelty claim is appropriately about a combination, with broad attribution. Quantum Control Machine is a particularly relevant omission now that a superposed program counter is central. *Change:* Add Quantum Control Machine and explain how Bennett's embedding and control-state cleanup satisfy the relevant synchronization obligations.
- **C8 4**: The component responsibilities and deferred mechanics are clear enough for the three intended readers. The remaining disagreements concern normative semantics rather than missing implementation detail. *Change:* Give one authoritative success-and-failure relation and make the thesis, theorem and acceptance tests reference it.

Suggestions:
1. Specify the approximation metric and numerical assurance behind channel comparisons. Diamond-norm bounds support compositional channel guarantees; phase-sensitive unitary bounds are needed for controlled use. Ordinary floating-point matrix agreement should remain evidence unless numerical error is rigorously bounded.
2. Clarify that the marker-only quantum-memory rule concerns explicit quantum-register access. Ordinary LLVM loads/stores in unmodified SQLite must still be accepted and coherently lifted according to the incoming memory model; otherwise §3.1 reads as contradicting the flagship demonstration.
3. Correct §3.3: Rust's distributed standard library normally includes embedded LLVM bitcode. Extract compatible bitcode where available; require rebuilding only when it is missing or unsuitable. Also replace unconditional mixed-major linking with supported combinations. See [rustc bitcode options](https://doc.rust-lang.org/rustc/codegen-options/#embed-bitcode) and [LTO compatibility](https://doc.rust-lang.org/rustc/linker-plugin-lto.html#toolchain-compatibility).
4. Add [Quantum Control Machine](https://arxiv.org/abs/2304.15000) to §7. Its injectivity and synchronization analysis directly informs the new step-machine construction; distinguish preservation of classical inputs through oracle embedding from unrestricted lifting of quantum control flow.

## opus

All seven round-2 blocking issues are resolved. Codex B1 (definedness) is resolved: the reference is the optimised bitcode, undef and poison are refined by freeze, immediate UB becomes a fault code, and the definedness assumption is recorded in the certificate (a residual gap remains: UBSan does not cover memory UB). Codex B2 (marker ABI) is resolved: handles are portable ptr or integer values, and quantum memory is reached only through markers. Codex B3 and muse B2 (bound exhaustion) are resolved: there is a region-level budget, a fault register and totality. Codex B4 and muse B1 (verification scope) are resolved: the permutation tier is defined after decomposition, domain D is exact, proof and evidence are labelled, and channel comparison uses a reference system. Opus B1 is resolved: the classical budget needs no per-loop annotation, the predicated step machine covers arbitrary CFGs, regions are total, and the rule is \"equals native, or is flagged\". The document is now close to founding quality. Two new load-bearing gaps remain, both in the semantics of classical code acting on quantum state. First, it never says what writes to quantum state that outlives a region mean: qstore over superposed contents, and in-place updates such as Sturm's `when(q) do x += a end`, the stated founding use case. Second, it presents garbage uncomputation as unconstrained scheduling policy, without the Silq/Unqomp validity condition. Without that condition a run-time scheduler can defer uncomputation past interference and produce wrong states that still pass ancilla-zero. Each needs one paragraph to fix. With both stated I would accept.

**Path to accept:** Add two paragraphs to §4.2, mirrored in the dialect and ISA specs. (1) Coherent memory and region interface: qload is a copy, qstore XORs or is refused, region inputs are preserved and outputs XORed, and in-place update requires an inverse via `__bennett_inplace(@g, @ginv)` or a library bijection, otherwise a compile error. (2) Uncomputation validity: garbage may be uncomputed only while its dependency set is unmodified, and must be cleaned before any non-permutation operation on a wire it depends on; all schedulers, compile-time and run-time, are confined to schedules that satisfy this, and the verifier enforces it. With those two in place I would accept. Defining the budget unit against the formal-model reference (suggestion 1) would then raise C6 to 5.

- **C1 4**: Thesis, decisions, the step-machine and totality semantics (§4.2), and the ladder now describe one system. The precise restatement in §0 ("defined, effect-bounded, within a classical budget … named fault outcome") makes the slogan honest. *Change:* State what classical code may do to quantum state that outlives a region: copy-on-read, XOR or refusal on store, and in-place only with an inverse (B1). Today "controlled-anything" is defined only for out-of-place oracles.
- **C2 4**: The premises I checked hold. Plugins cannot register llvm.* intrinsics. Define the reference for fault codes (see suggestion 1).

Name unwinding as either step-machine control flow or a fault code.

Exhaustive checks count as proof and sampled checks as evidence. Channel comparison uses a reference system, and ε composes. "Equals native, or flagged" carries fault rates per rung. The set of faulting inputs may therefore change with the compiler's region pipeline, and the theorem's "same fault code" has no native counterpart. *Change:* Define the budget unit and the expected fault code against the ISA formal-model interpreter run on the outlined region, before the region pipeline. QIR is critiqued precisely, Quil/QAM, eQASM, Knill, Spire and Qrisp are now credited, and Silq/Unqomp are adopted for budgeted uncomputation. Suggestions:
1. Define the budget unit and the reference for fault codes. "Steps" should be counted by the ISA formal-model interpreter on the outlined region before the curated region pipeline. Compiled artefacts must never fault where that reference does not; they pad internally as needed. That makes the fault set a property of program plus budget, not of compiler version. §5.1 part 1's "same fault code" should then compare against that reference, because native execution cannot produce budget or unmodelled-effect codes.

3. UBSan does not catch out-of-bounds or use-after-free accesses, or uninitialised reads. Name ASan and MSan, or a checked reference interpreter, as the definedness classifier. Say that the instrumented build only classifies inputs and is distinct from the uninstrumented comparison binary built from the same optimised bitcode.
4. Add to §7: QCOR/XACC (C++ quantum kernels via a clang plugin, compute/action/uncompute, automatic ctrl/adjoint); Qiskit's classical-function compiler and tweedledum/RevKit (oracle synthesis from classical code); ProjectQ's Compute/Uncompute; and REVS (Parent–Roetteler–Svore), alongside PRS15.
5. Give the dialect spec a reference semantics from marker programs to the ISA formal model, so a competing plugin can be conformance-tested at spec level and not only by native differential.
6. State that any code that touches handles or measurement results runs in the VM's classical-control tier, never in host native code. This reconciles "classical tier = host" with measurement feedback and with the fail-loud handle check.
7. Name exceptions and unwinding (invoke/landingpad, Rust panics, C++ throw) in coherent regions: either as step-machine control flow or as a fault code, next to setjmp in §9.11.
