## Blocking issues

- **[codex] B1** (§§3.6, 4.2, 5.2, 14.1–14.3): The step construction still does not consistently implement its table. Section 3.6 requires every write to use compute-and-exchange with displaced history, whereas oracle_call, perm_call, free, and several call/return updates specify direct reversible operations and different inverses. In particular, repeating lift.free cannot undo it: the forward operation clears live_i, so its repeated live-entry search no longer finds that allocation. Success is also inconsistent: qjump n is not prohibited, reaches HALT with faulted=0, and commits success without lift.retval; larger constant targets have no dispatch predicate. *Fix:* Define each row as an atomic old-state transition with an explicit outcome and a complete reversible realization. Distinguish assignments that retain displaced values from direct permutations that do not; give both their complete scratch-cleaning inverses. For free, retain the selected allocation identity and undo the live-bit change without repeating the forward live-entry validation. Validate all direct and indirect targets, and require that only lift.retval produces a successful terminal outcome. Prohibit jumps to HALT, or introduce an explicit terminal-outcome field; I recommend prohibiting such jumps.
- **[codex] B2** (§§3.2, 3.6–3.7, 4.2 lift.call/lift.ret/lift.alloc, 7.2): The procedure model lacks a defined mapping from separately serialized lprocs to the oracle's pc range, an exact activation-record layout/R_f, input-to-location initialization, and root-return behavior. Its counters also have a concrete representational contradiction: atop:wire[Ac] can never equal 2^Ac, and sp:wire[Sc] cannot hold the allowed full-stack endpoint 2^Sc. The full-width-comparison instruction does not prevent wrapping when those accepted values are stored. *Fix:* Define canonical procedure/instruction addresses over the linked lifted closure, exact activation records, parameter/result bindings, initial fp/depth, and invalid-return behavior. Separate address-index widths from occupancy-counter widths: a capacity of 2^A needs an occupancy counter of at least A+1 bits, with additional widening for prospective increments. Validate all launch limits against actual region capacities before execution. Either reject lift.ret outside a procedure statically or give it a named underflow fault; I recommend static rejection where provable and a defined fault otherwise.
- **[codex] B3** (§§4.2, 4.7, 5.1, 7.1–7.2): The memory model still admits different machines. Two zero-size allocations return the same base and remain live, contradicting free's unique-match rule. The classical initial bump address, initial live records for globals, and separation of globals from a heap starting at zero are unspecified. Heap limits are not explicitly bounded by the byte region. Finally, lifted accesses address only the implicit mem region, while lifted call forms provide no interface-memory arguments; adding mem parameters therefore does not define how a lifted oracle accesses caller-owned regions. *Fix:* Specify initial memory, reserved ranges, allocator state, and allocation-table contents from the layout, including the classical bump base. Define zero-size allocation so free is unambiguous: reserve a distinct address for each allocation, or introduce allocation identities with a deterministic free rule; I recommend distinct reserved addresses. Require allocations and whole accesses to fit the physical region, and require each bounds check to match the access's address version and length. Define address-to-region translation or explicit region operands, and carry memory arguments through every applicable lifted call form.
- **[codex] B4** (§§3.3, 4.1–4.2, 4.6–4.7, 5.1, 9.4): The instruction typing and ownership contract remains incomplete. Named regions have no specified consume-and-reproduce ownership/version rule comparable to bundles. Several classical forms and conversions are blank; operand-width compatibility and location aliasing are unstated. load.iN permits widths for which N/8 is not an integer, and measurement can produce an iN outside the declared 1–128-bit classical type range. Lifted call forms also omit classical and memory arguments supported by callee signatures. *Fix:* Publish a typed operand/result schema for every opcode, including literal rules, permitted aliasing, conversion widths, memory widths, and measurement limits or chunking. Treat a region as one owned value with explicit implicit-version threading through accesses and calls, or define an equivalent exclusive-reference discipline; I recommend the same consume-and-reproduce convention used for bundles. Make all call forms carry the complete declared interface and require signature agreement.
- **[codex] B5** (§§6.1–6.3; T5; suite F): The new transfer table still cannot justify T5. A predicated qexch does not simply swap provenance: its output is selected between the old operands and depends on the predicate. oracle_call omits dependencies on interface memory, and action-call rules omit mutable-memory effects. Consequently, a copied oracle result can retain an apparently open window after its actual memory dependency changes. Several initialization, control, and cleanup-transfer cases are also absent. *Fix:* Define transfer functions over immutable value versions, active control context, and conservative memory read/write sets for every operation. Predicated exchange must include both possible operands and its predicate unless a stronger checked relation is available. Calls must expose memory and wire dependency/effect summaries. Bind each cleanup to the exact computing sequence and the versions needed by its inverse, rather than inferring safe cleanup from the perm label alone. Retain the corrected logical-amplitude interpretation of T5.
- **[codex] B6** (§5.5; §6.1; suite F): The matched nested cleanup now permits a nonzero fault register, but its version rule is contradictory. The first call changes tgt, so a second call cannot both consume the current target and have the same target operand version as the first call. Requiring the two calls' operand versions to match also does not describe the corresponding returned fr version. *Fix:* Define a matched cleanup invocation that consumes the first invocation's returned tgt/fr versions and requires its original input and memory values to remain available unchanged. The two calls share a dynamic invocation identity, token, and callee identity; their target versions are predecessor/successor-related, not identical. Alternatively remove explicit second-call cleanup and retain the result until prefix reversal. I recommend the explicit matched form.
- **[codex] B7** (§§3.4, 7.3–7.4, 9.4; T4): The R model still does not define dynamic SSA instances in loops: the same static non-parameter definition executes repeatedly, but is declared immutable within one activation. It is unclear which instances survive or how reversal resolves them. LIFO call identity also does not establish the corresponding return state when intervening CC operations modify shared memory or quantum registers. Device operations introduce array types absent from the ISA, and ENTROPY_EXHAUSTED has no defined fault-code representation. *Fix:* Define dynamic SSA environments explicitly, retaining each executed definition until reversal or specifying a checked recomputation scheme; I recommend retained dynamic instances as the reference model. Record complete invocation boundaries and require return-state dependency versions to match, or reverse the intervening suffix first. Specify fault-prefix reversal. Give device arguments/results an expressible representation, versioned operation signatures, fault encodings, and exact state-restoration rules, including allocation-table entry creation and block-sector presence.

Custom resource aggregation and validation of rates, durations, weights, and matching entries are also incomplete. *Fix:* Use a closed JSON expression AST, or fully specify textual parsing and arithmetic; I recommend the AST. Define table indexing, exact-mode expressions, errors, and numeric evaluation. Give gate realizations explicit operand-class patterns, arity/control/parameter constraints, and deterministic matching rules. Resolve decompositions to specified templates or versioned definitions. Define aggregation for every resource kind, treatment of classical/effect time, and validation of nonnegative finite costs and objectives.

Eligibility tracks quantum registers but not shared classical memory, devices, or intervening host services. There is no CC instruction that raises HOST_REQUEST, no response-to-result binding, and no complete close/handle-invalidation rules for measured or failed runs. *Fix:* Define an invocation tree or another ownership rule under which every operation is reversed exactly once; I recommend R records owning their nested Q inversions. Track dependency versions for all shared state and define exclusive ownership during active runs. Specify the host-service request instruction, response types, suspension/resumption transitions, and reversal policy for such requests. Define close transitions for completed, failed, and reversed runs, plus measurement consumption and handle invalidation. Restrict reversal where required dependencies or reversible records are absent.

- **[opus] B1** (§4.2 lift.free / lift.alloc; §3.7; §7.1–7.2): Lifted allocation is neither reversible nor representable as written. (a) lift.free matches 'the unique i with live_i ∧ base_i = p' and flips live_i 'with no displaced value'. The control of that controlled-X depends on its own target, so the match cannot be uncomputed. The listed inverse ('same op') also finds no live entry after the free, so it faults instead of restoring the entry. (b) n = 0 is a valid allocation that does not advance the bump pointer, so the next allocation shares its base. 'The unique i with base p' is then false, in both the lifted and the CC/R allocator. (c) §7.2 uses Ac and Sc as region-size exponents (2^Ac table entries, 2^Sc stack cells), while §3.2/§3.7 use them as counter widths that must represent every limit without wrap. With those widths, `atop = 2^Ac` and `sp+R_f > 2^Sc` cannot be represented. (d) Nothing bounds heap_base + heap_limit by 2^H, so an allocation can extend past the end of `mem`. That contradicts §7.2's claim that an access wrapping past 2^H is outside every allocation. *Fix:* State: match_i = (i < atop) ∧ (base_i = p), computed without reference to live. flag = ¬∃i: match_i ∧ live_i. Then live_i ^= match_i ∧ ¬flag, and match_i is uncomputed. The inverse is that same controlled flip on live_i, recomputing match from base only. Alternatively, displace the index i into the frame and use exchange-back; I would take the base-only match. Require allocation bases to be pairwise distinct by allocating max(n, 1) bytes (zero-size allocations stay unaccessible because boundscheck uses size n), in both lifted and CC/R. Introduce separate exponents A_tab and S_cells for the table and stack sizes, and require Ac ≥ A_tab + 1 and Sc ≥ S_cells + 1. Require heap_base + heap_limit ≤ 2^H, checked at load.
- **[opus] B2** (§7.2 layout; §4.2 lift.boundscheck; §5.1 interface regions; §7.1): The lifted address space contradicts itself and the north star. heap_base = 0, so the first successful allocation returns the null pointer, and C code testing `p == NULL` diverges from native. I would take the mapping, since the north star's rung 4 needs it.
- **[opus] B3** (§5.6 structural borrow frames; §12.1 `borrow_frame_VWV`): The structural rule ('V; W; V⁻¹ with V permutation-only, W touching neither the borrowed wires nor any wire V reads') certifies restoration without checking it, and its meaning depends on an undefined word. If 'reads' includes V's targets, W is disjoint from V altogether and the frame is vacuous: it cannot express the standard dirty-ancilla pattern, where W uses the borrowed wire as a control. If 'reads' means controls only, the rule is unsound. Take V = `cx b y`, W = `cx y z`, V⁻¹ = `cx b y`. The borrowed wire b is restored on every basis value, but z ends as z ⊕ y ⊕ b, so the public output depends on b and entangles with it. A `structural` claim of kind `borrow_frame_VWV` would label this proof. *Fix:* Replace the rule with the toggling lemma and state its side conditions. A frame V; W; V⁻¹; W is restoration-safe if all of the following hold. V only XORs into borrowed wires functions of wires X, where W writes no wire in X. W's targets lie outside X, outside the borrowed set and outside W's own controls. Every gate of W has at most one borrowed control, so W's effect is affine in b. The net effect is then b-independent and b is restored, which is the pattern used for dirty-ancilla MCX (Gidney; Häner–Roetteler–Svore). Say explicitly that 'touches' includes targets. Frames of any other shape require an exhaustive or library T3 claim. A minimal alternative is to delete the structural rule and rely only on exhaustive or library frame certificates. I would take the lemma, because the north star's finite-D argument for large dirty pools depends on it.
- **[opus] B4** (§9.2 identity; §12.2 bindings; §16.2 instr): Content identity omits semantic inputs, and canonical bytes are not unique. Two oracles that differ only in a baked-in table share their hash. Their certificates validate against each other, and 'equal-hash duplicates deduplicate' at link silently substitutes one for the other. Separately, the grammar admits a destination prefix `r = op …`, the §4 forms write `→ w`, and the example writes the destination as a trailing operand (`lift.add rx one r`). Two producers can therefore emit different bytes, and different hashes, for one program, and a parser cannot tell destination from operand except by convention. *Fix:* Define the hashed envelope of a symbol as: its canonical function bytes; the canonical bytes of every `data` and `layout` entry it reaches (by name, in sorted order); the header's ptr_width and ISA major; and the callee hashes, substituted as now. Interface hash and closure hash are both computed over this envelope, and certificates bind to it. Fix one destination spelling: I recommend `w = op a b` everywhere, with §4 forms rewritten to match. Recompute the example's hash under the new spelling.
- **[opus] B5** (§3.6, §3.7, §4.2 (indices, terminators, lift.ret/lift.retval)): The index space I[0..n) is not defined, although index values are data. The text says an oracle body is 'a sequence … over the oracle's locations and its lprocs' locations'. But the grammar has named blocks and separate lproc functions, and lprocs may come from other linked objects. No rule fixes the order of blocks, the placement of lprocs, or what happens when a block does not end in a terminator. lift.call pushes k+1, entry indices are taken from this layout, and qjumpr takes a runtime integer, so a body that computes jump targets means different things under different flattenings. Also: the terminator list omits qbranch. lift.ret executed with no active record (depth 0, at oracle top level) is undefined. Whether lift.retval inside an lproc halts the oracle with success is unstated. *Fix:* State: I is the oracle's blocks in text order, followed by the lproc closure in a canonical order (sorted by closure hash, with the SCC index for mutual recursion), each block contiguous. A block must end in a terminator (qbranch added); fallthrough is ill-formed. Branch and call targets are written as labels in the text. qjumpr operands MUST be produced by a `lift.label ^b → w` constant, so no producer writes raw indices and executors may re-index extensionally. lift.ret with depth = 0 faults FAULT_UB_TRAP. lift.retval inside an lproc is ill-formed (suite F).
