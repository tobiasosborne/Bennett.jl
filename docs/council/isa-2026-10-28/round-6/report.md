## Blocking issues

- **[codex] B1** (§§3.6, 4.2 lift.alloc; T2; core/S0): The mixed-row inverse is repaired, but the indexed A-row destination remains unresolved. lift.alloc writes w, alloctab[old_atop], heap_used and atop. Its inverse says to exchange every assignment slot back without specifying the exchange order, while addresses are evaluated from the current inverse state. With old_atop=0, an inverse following the listed slot order exchanges the table slot with alloctab[1], leaving alloctab[0] live; the slot then cannot uncompute cleanly. Reversing the exchange order instead restores the correct state. At table capacity, the former interpretation can address outside the table. *Fix:* State that an A row first undoes all destination exchanges in reverse forward-exchange order, then uncomputes all slots from the restored pre-state. Print lift.alloc's inverse exchange order: atop, heap_used, alloctab[restored_atop], w; only afterwards clear the four slots. Alternatively retain effective addresses in the frame. I recommend reverse-order exchanges for the existing rows.
- **[codex] B3** (§§4.1, 7.4; T4; core/S0): The pure-suffix restriction fixes the original interference examples, but segment reversal is not defined consistently for nested cancellations. Only whole-run reversal explicitly skips reversed segments and uncall frames; segment uncall still reverses the segment's frames, nested segments included. Let R function f call g, immediately uncall g, then return, with g performing one clock.read. Calling f leaves the clock unchanged. A subsequent legal uncall f encounters both the inner uncall and g's already-reversed effect frame. Applying the stated segment traversal again decrements the clock a second time; skipping the canceled frames does not. The inverse treatment of an uncall frame inside the selected segment needs an explicit rule. *Fix:* Use the same cancellation-aware traversal for every history reversal: undo only unreversed ordinary frames, skip the effects of already-reversed frames and uncall markers, and define how their records are retired. Apply this recursively when uncalling an outer segment. Alternatively prohibit uncall of any segment containing an uncall; I recommend the shared traversal because it preserves nested compute-copy-uncall.
- **[codex] B10** (§§11, 12.1–12.3; contract/S0): The certificate's realisation context is still incomplete. One root schedule can invoke the same callee with the same variant and inherited control count at multiple paths, using different classical arguments, budgets, synthesis shares or cleanup choices. Those invocations have identical current subject fields and error-map keys, yet can denote different realised and reference unitaries. Thus 'build the realised unitary U of the subject' is not a unique operation, and multiplying one invocation's error bound by the shared multiplicity can understate the total error. Adding variant and control count fixes only part of the previous issue. *Fix:* For 0.6, explicitly define each region/key error entry as a verified common upper bound over every matching invocation in the bound root schedule, including its resolved arguments, budget and path-dependent realisation; require the claim to check all those contexts. I recommend this conservative default. Alternatively identify each subject by its invocation context or resolved sub-schedule identity, including arguments and budget, and compose separately keyed bounds.
- **[codex] B11** (§12.1 Diamond-norm SDP; contract/S0): The statement that nonnegative leading principal minors establish positive semidefiniteness is false. For the one-qubit channel difference Z(·)Z−id, J has only J[0,3]=J[3,0]=−2 nonzero. Every leading principal minor of both J and −J is zero, although both are indefinite. Consequently the permitted fallback can accept Y=0, mu=0 and bound=0: all its leading-minor tests pass, but the actual diamond distance is 2. This is an unsound acceptance rule, not a request for a more detailed numerical procedure. *Fix:* Delete the leading-principal-minor alternative. The minimal correction is to require all principal minors to be nonnegative, with rigorous rejection of inconclusive tests. A sound Hermitian LDL† procedure with appropriate singular-pivot handling is another option. I recommend retaining the PSD obligation and using all-principal-minor verification as the simple conservative default until a faster sound procedure is specified.
- **[opus] B1_UNCALL_OVER_MEASURE** (§7.4, §4.1 uncall, §3.3 handle table; core/S0): Segment uncall is legal in CC. A CC callee may execute `measure` (and `qreg.free` on hardware, §17 item 14), and nothing excludes such a segment from uncall. The handle table defines the reversal of a `measure` frame as 'the handle states before that frame'. So `call @f` (where f measures q) followed by `uncall @f (...)` makes q live again over wires that were collapsed and released. That is unphysical, and T4 claims a restoration that cannot happen. Some implementers will restore the handle and others will trap, so the semantics diverge and are unsound. The parenthetical 'a run containing measure is not reversible' governs only whole-run reversal (§10), not segment uncall. *Fix:* Add to §7.4: 'An `uncall` whose segment S contains, at any nesting depth, a `measure` frame (or, on hardware, a `qreg.free` frame whose cleanliness was not verified) is a CC trap with no state change.' Change the handle-table reversal row to say that reversal of a `measure` frame never occurs, because both segment uncall and whole-run reversal exclude it. Add the case to suite A. The alternative is to forbid `measure` in any function reachable from a callee that is later uncalled, as a static suite-F rule. That is harder to check, so I would take the dynamic trap.
- **[opus] B2_PSD_ACCEPTANCE_UNSOUND** (§12.1 diamond-norm SDP, encoding paragraph; contract/S0): The checker may establish PSD by 'any procedure that rejects whenever it cannot prove every leading principal minor nonnegative'. Nonnegative leading principal minors do not imply PSD: diag(0,−1) has minors 0 and 0 and is not PSD. A checker following this rule accepts invalid witnesses, so a false diamond bound can be certified, and it disagrees with an LDLᵀ-based checker on the same certificate. Interval LDLᵀ also cannot soundly prove PSD when a pivot is exactly zero. *Fix:* Require the checker to prove positive definiteness of Y−J(Φ), Y+J(Φ) and mu·I−Tr_out(Y) by an interval Cholesky (or LDLᵀ) factorisation in which every pivot's interval lower bound is strictly positive, and to reject otherwise. State that producers make witnesses strictly feasible by replacing Y with Y+δI and mu with mu+δ·d_out; this keeps the bound valid, since ‖Φ‖◇ ≤ mu+δ·d_out ≤ `bound`. The alternative is to require proof that every principal minor (not only the leading ones) is nonnegative. That is exponential and still fragile at zero, so I would take strict positive definiteness.

## opus

Draft 0.6 resolves all 19 round-5 blockers. Two of them, the certificate-SDP pair codex B10 and muse B5, are only partially resolved because of a new defect in the PSD rule they introduced. I checked the A+D inverse lists by hand. C1–C5 and their inverses clear every slot, and the record XORs use the restored sp/fp. R1–R5 and their inverses undo delivery at the callee fp, and recursive self-calls (delivery into r ∈ L_f) work. Example 2's numbers are consistent: R_sum=16, n=16 needs 272 ≤ 2^9 cells, depth faults iff depth_limit ≤ n, and n>16 hits MEMFAULT at 4112. The diamond-norm SDP as printed is mathematically correct. Y±J⪰0 with μI⪰Tr_out Y is the Hermiticity-preserving dual via Y0=(Y+J)/2 and Y1=(Y−J)/2, and it bounds the full norm, not half. I could not run a hash recomputation in this session, so I rely on the editor's mechanical check for the printed hashes. Two new S0 issues remain, each a one-sentence fix. (Core) Segment uncall in CC can reverse a segment containing `measure`, which would revive a collapsed, released register; this is unphysical and makes T4 false. (Contract) The PSD acceptance rule ('leading principal minors nonnegative') is unsound: diag(0,−1) passes it. Neither is a regression. The suggestions mainly cover nested-uncall transparency, A-row exchange order for alloc, epsilon_share circularity and the citation of the SDP. Core verdict: revise because of B1; it becomes accept once that sentence is added.

**Path to accept:** Two sentence-level changes. (1) Core: in §7.4, make `uncall` of any segment that contains a `measure` frame (or, on hardware, an unverified `qreg.free`) a CC trap with no state change, and mark reversal of a `measure` frame as unreachable in the §3.3 handle table. (2) Contract: in §12.1, replace the 'leading principal minors nonnegative' rule with a requirement to prove strict positive definiteness, by interval Cholesky with every pivot's lower bound > 0, for Y−J, Y+J and mu·I−Tr_out(Y). Producers make witnesses strictly feasible by Y+δI and mu+δ·d_out. With these two changes I return accept for both scopes. After that, the highest-value improvement is making a reversed segment plus its `uncall` frame transparent, so that nested compute/uncompute works.
