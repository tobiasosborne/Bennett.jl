1. 3328319 (src/softfloat_dispatch.jl; functions `_sfd_check_call`, `_sfd_split`, `_sfd_components`, `_sfd_subst`). Float64 functions are compiled by tracing them on a wrapper type, SoftFloat; the code compares, call by call, which method is selected for Float64 arguments and which for SoftFloat arguments, and declines to compile when they differ. This commit handles a call whose argument type is a Union of concrete types by splitting it into the concrete calls and pairing each Float64 case with the corresponding SoftFloat case. The author notes that this pairing is assumed rather than proved. Please check the pairing on Unions of three or more types, `Union{Float64, Int, Missing}`, nested tuples, `Some{Float64}`, a Union that contains a type with its own SoftFloat-specific method, and a Union-typed callable. Already known, no need to report: calls that select different Base methods such as `map(f, ::Number)` versus `map(f, A)`.

2. 95b2d9c (src/narrow.jl; `_narrow_promotions`, `_narrow_promoted_use`). The option `bit_width=W` re-types a function's integer operations from the source width S down to W bits. This commit lets a sign or zero extension from iS to a wider integer be dropped when all its uses are comparisons against a constant, comparisons against another extension of the same kind, or a truncation back to iS. The code comment has a case table. Please check that table from first principles — especially constants at the edges of the W-bit signed and unsigned ranges, constants that do not fit in iS, the cases folded to constant true or false, a comparison between extensions from two different source widths, and whether every kind of use of the extended value is found (a use in another basic block, in a phi, as a call argument, as a select condition or value).

3. 5952275 (src/extract/instructions.jl; `_alloca_is_fresh`). A stack slot is "fresh" if nothing has written it since it was created; a zero-fill of a fresh slot is treated as a no-op and removed. This commit makes the check follow pointers derived from the slot (GEP, select, phi, casts). Please check whether any earlier write to the slot is still missed: a derived pointer defined in another block, a loop back edge, an integer round trip of the pointer, a pointer loaded back from memory, a call that receives the pointer, a memory copy where the slot is both source and destination, atomic or volatile stores, a store of a vector of pointers.

4. a83fe6b (src/tabulate.jl; `_tabulate_impurity`). `strategy=:tabulate` evaluates the function on every input at compile time and emits the table. This commit allows that only when Julia's effect analysis reports the function as side-effect free and consistent (or not reading mutable memory), or else when the ordinary expression compile of the same function succeeds. Please check whether a function whose result can change between compile time and run time still gets tabulated. Already known, no need to report: a function returning the identity of a newly allocated object, and a function carrying an incorrect `Base.@assume_effects` annotation.

5. f2ae03f (src/extract/module_walk.jl `_check_synth_ptr_read`, `_check_synth_ptr_gep_loads`, array strides; src/extract/instructions.jl GEP "Case B" / "Case C" and the load handler). Constant globals are turned into byte images. Pointer-typed fields get placeholder bytes that identify the pointee and have no meaning as integers; this commit declines any integer read that overlaps such bytes, and places array elements inside struct globals by their allocation stride. Please check the remaining ways a program can read a global: a chain of two GEPs, a load wider than one byte that overlaps the pointer bytes only partly, a memory copy of part of the global, a pointer field inside a nested struct or an array of pointers, a negative or out-of-range constant index, packed structs, arrays of i1 / i24 / i128, and a big-endian data layout.

6. 9198a7a and 2cd65f2 (src/ir_types.jl field `ParsedIR.width_dependent_ops`; src/narrow.jl; src/narrow_differential.jl, new; src/extract/callees.jl; src/Bennett.jl). With `bit_width=W`, two readings of the function are now produced — from LLVM's unoptimised output and from its optimised output — and each is re-typed to W bits. If only one reading can be re-typed it is used. If both can, both are compiled and their circuits are compared on every input (up to 16 input bits; a fixed sample of 4096 inputs above that); when they differ the compile is declined with an error. Narrowing is also declined when the function uses a bit-width-dependent LLVM intrinsic (count leading / trailing zeros, bit reverse, byte swap, funnel shifts). Please check: (a) the comparison itself — are the two circuits fed the same inputs in the same argument order and bit order, are outputs compared as raw W-bit patterns, is an input on which one circuit reports a failed loop bound treated as a difference, is the sample deterministic; (b) whether a cached result can be returned without the comparison having been made, including after one of the two readings was compiled separately by an earlier call with `optimize=false`, and across the `strategy` and `mem` options; (c) whether any place that constructs a `ParsedIR` loses the new field; (d) other LLVM intrinsics whose meaning depends on the bit width and that are not on the list (population count is claimed to be safe — check; absolute value with the minimum-value flag; saturating arithmetic; multiplication with overflow flag; min/max); (e) programs with two or three arguments, tuple arguments, and W equal to S. Already known, no need to report: with `optimize=false` only the unoptimised reading is used and it is not compared; and when only one reading can be re-typed it is used without comparison.
